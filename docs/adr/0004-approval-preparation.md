# ADR-0004：审批准备先于执行恢复

日期：2026-10-18。状态：SPEC-010 采用。

批准记录只有在身份、工具、参数和策略绑定可验证，并能处理并发/过期/未知结果时，才能参与工具执行。当前没有单次领取和业务确认协议，因此将准备/决定作为独立增量，不让 approved 绕过现有 Runtime allow/deny。

可选准备客户端不持有业务 callable；参数仅在本地按严格 JSON 类型规范化并 HMAC，策略为含 revision/规则顺序的版本化快照 SHA256。服务保存不可覆盖的绑定元数据，按 action ID 幂等，数据库时钟定时效，行锁串行化决定。重试不续期，不提供重开/删除。HMAC 密钥不上传，动作说明由可信宿主提供。

producer 只创建，reviewer 只读/记录决定；两种显式凭证与 Trace token 分离，默认关闭，固定服务端 reviewer 不伪装成多用户身份。Dashboard 审核状态独立，离开即清空凭证，写入未知先刷新。复用模块化 Collector 单体和 PostgreSQL，新增迁移3，不引入额外协调基础设施。

代价：批准暂时不能推动 Agent 继续；摘要不能让审核人审阅关键参数，后续必须补足明确预览与单次执行/确认协议。可信宿主、数据库管理员和同进程代码仍在信任边界内，没有对抗恶意同进程代码或不可篡改审计的保证。参考来源和适用限制见 [审批研究笔记](../../resources/notes/approvals.md)。
