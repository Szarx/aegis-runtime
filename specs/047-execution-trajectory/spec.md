# SPEC-047 执行轨迹与审批排查

以合成的慢模型、人工审批和宿主恢复为验收案例。用户应能从列表发现关键动作，在轨迹中定位最慢调用和触发规则，再核实批准后的实际执行状态。

- AC4701 列表和详情单独呈现 Trace 状态与已接收治理信号。信号优先级为拒绝、受控工具异常或取消、审批请求快照、审批后工具返回。每条 Trace 给出一项主信号。动作最终状态由审批记录提供。
- AC4702 轨迹默认按精确开始时间和 Span ID 排序。Agent、模型、工具、治理四条时间带与步骤表共享选中节点。支持现有节点搜索、类型过滤、耗时排行、键盘导航与深链。每页至多 50 步，时间轴保持全 Trace 尺度。原树视图保留。无效时间显示未知，并从时间带排除。
- AC4703 审批节点可按 Action ID 打开执行审批的精确服务器查询。只使用独立 reviewer 凭证，包含已不在首页的记录。保留人工展开和参数确认，显示审批决定与执行状态，支持返回原 Trace 节点。
- AC4704 未连接页面提供离线可直接打开的只读合成演示，复用真实轨迹组件和信号文案。演示包含同一 Action 的请求和恢复、模型耗时及确认结果。
- AC4705 验证 API 变更仅为可空治理信号和可选 Action ID 参数。保留原授权、JSONB 与 SQL 迁移，兼容旧 Collector 缺少信号字段。验证真实 PostgreSQL、浏览器窄屏和完整测试。

本轮采集范围为已有 Trace Span 与审批记录。跨会话、轮次协议、实时流和首 Token 时间留待后续定义。
