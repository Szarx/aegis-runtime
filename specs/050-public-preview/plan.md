# 实施方案

1. 盘点 Git 候选、所有 SPEC、当前产品文档与历史对象，形成公开分类和能力索引。
2. 重写面向读者的入口，整理历史与现状，增加 Apache-2.0、第三方分发说明和安全报告入口。
3. 将本机材料检查变成可提交工具，并在 CI 中复用；为历史、秘密不回显和文档失效建立有意义的失败验证。
4. 冻结候选字节运行完整验收；从暂存树导出干净副本，使用独立 Compose 名称和端口从在线官方源构建/启动，实际发送合成数据并核对查询。
5. 审查暂存与提交，使用原 main 快进交付，等待该 SHA 的远端 CI，再切换公开并匿名验证。

不移动历史契约文件，不更改第三方原始文件，不提交本机日志和临时密钥。原始证据在忽略目录，公开只保存必要的无秘密摘要。包仍保持开发版本；开源仓库不等于包注册发布。
